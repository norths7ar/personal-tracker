# Personal Tracker

一个自用的记账、饮食记录与待办工具。记录日常支出和吃了什么，也留住想推进的事情。项目围绕自己的使用习惯持续调整，以桌面浏览器为主要使用界面。

## 功能

- **待办事项**：记下想做的事，调整顺序，选一件开始；支持完成、恢复和编辑，不要求分类或设定期限。
- **日常记录**：自然语言草稿在当前浏览器自动保留；提交后先保存原文与日期，再后台解析。高置信度且字段完整的记录自动入账，其余在「待处理」补全、确认、重试或丢弃。也可通过次级入口手动记一笔或一餐。
- **账目管理**：在「流水」查看、筛选和编辑交易，支出可选填生效期；在「周期计划」管理周期付款及一次性预计支出，确认付款后生成交易。
- **饮食记录**：保留原始描述，可选填餐顿、时间、食物和主要食材；时间分布只统计有时间的记录，食物频次只统计已填写的食物。
- **统计分析**：按时间和分类查看收支，区分实际支付与按生效期逐日分摊的成本，并提供月度预算参考。
- **设置**：在页面管理模型服务、密钥、分类、餐顿标签、提取提示词与访问密码；分类修改仅影响今后的选项，不修改历史记录。

录入区的常用词来自近 60 天的高频菜名和至少出现两次的消费描述，可固定常用短句；点击只追加到输入框。提交被服务端接收后可以离开页面；解析失败或重启中断的任务保留原文，可在「待处理」重试。部分成功的批次只重试未入账片段，已入账记录不会重复写入。

付款计划与实际交易分开记录，确认付款后才计入账目。生效期包含起止两天，仅支出可设置，留空则归属付款日；费用以整数分逐日均摊，余数从最早一天起分配，再聚合到月、年。先用后付也按生效期归属，分摊不产生额外付款。当期分析仍统计截至今天的金额。关联退款在退款日抵扣原支出分类，不重复计作收入。

周期计划可选配置确认付款时自动填入几个月或几天的生效期，从计划应付日开始；下一次提醒仍按实际付款日期及原周期规则推进。「月度固定成本参考」仅折算周期计划的月均金额，不包含一次性计划或已入账生效期费用，也不额外计入预算用量。饮食统计基于已有记录，不把缺失记录当作没有进食，也不推断营养摄入。

## 实现

前端使用 React、TypeScript、Radix Themes 和 Vite，图表使用 ECharts；后端使用 FastAPI，数据存储在本机 SQLite 数据库中。前端 API 类型由后端 OpenAPI 定义生成。

应用在本地运行，不依赖云端数据库。自然语言解析会将输入内容发送给配置的 LLM 服务，因此并非完全离线。配置保存在独立的 `data/settings.db`，API Key 加密保存，主密钥为 `data/.key`，登录密码保存校验摘要。真实数据与凭据不纳入 Git，不再读取 `.env` 或 `config.yaml`。

应用代码按领域组织：`backend/` 包含共享基建及设置、待办、饮食、账目、录入模块；`frontend/src/features/` 就近组织页面、子组件与样式。`service/` 管理实例生命周期，`scripts/` 提供维护命令，`tests/` 与 `docs/` 分别保存关键风险测试及操作文档。

提示词在设置页逐项编辑、保存或恢复默认；未自定义的条目自动跟随代码内置模板。保存时校验必需占位符，每次提取使用模型、分类、密钥及提示词的同一份快照。

## 本地运行

日常运行环境为 Windows，使用 Python 3.14、uv、Node.js 24+ 和 pnpm。在项目根目录准备环境：

```powershell
uv sync
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
uv run python -m service start
```

浏览器访问 <http://127.0.0.1:18080>，在「设置」填写模型服务与 API Key。新实例默认不启用访问密码；启用后可修改密码或使其他登录失效。模型、分类、提示词与访问设置保存后生效，不中断已经发出的模型请求。

服务管理程序支持 `start`、`stop`、`restart`、`status`。生命周期由本项目管理，外部管理软件只调用[服务接口](docs/service-management.md)，不直接控制进程或内部运行文件。没有登录自启或定时备份任务。更新依赖后同步环境，前端更新后重新构建，再按需重启。

业务数据库固定为 `data/tracker.db`，设置页只读显示位置。备份时停止服务并保存整个 `data` 目录，尤其应配套保留 `settings.db` 与 `.key`；密钥丢失不能解密已有凭据。恢复前另存当前数据，使用配套备份恢复，不用新密钥覆盖旧密钥。若只需账目快照，可运行 `uv run python -m scripts.backup_sqlite`，默认保存到 `data/backups/rolling`；需要长期保留的历史备份放在 `data/backups/archive`，不参与滚动清理。

## 开发

开发时先停止占用端口的后台实例，再分别运行 `uv run uvicorn backend.app:app --host 127.0.0.1 --port 18080 --reload` 和 `pnpm --dir frontend dev`。隔离验证可用服务管理程序的 `--data-path` 和 `--port` 指定独立实例；直接运行后端时使用 `TRACKER_DATA_DIR`，前端开发代理可通过 `VITE_API_PROXY` 指向隔离端口。这些是实例启动参数，不是页面中的数据位置设置。

`pnpm --dir frontend generate:api` 离线生成 API 类型，不启动服务或初始化数据。Python 使用 Ruff（行宽 100），执行 `uv run ruff check .` 和 `uv run ruff format --check .`；前端使用 ESLint、Prettier 和 tsc，分别提供 `lint`、`format:check`、`type-check` 命令。`uv run python -m unittest discover -s tests -v` 检查数据库写入、关联一致性、备份与开销统计；`pnpm --dir frontend test` 检查净支出及累计走势计算。

VS Code 直接打开仓库根目录，项目设置使用 `.venv` 解释器及仓库导入路径；保存行为、默认格式化器和 Pylance 诊断级别沿用用户配置。前端项目规则与工具版本由仓库配置及锁文件确定。
